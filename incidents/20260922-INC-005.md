\# 20260922-INC-005 — Backup e recuperação com RMAN e Flashback



\## Ambiente



\- Oracle Database 26ai Free

\- Docker

\- PDB: FREEPDB1

\- Schema: APP\_VENDAS

\- Ferramentas: RMAN, SQL\*Plus e PowerShell

\- Modo ARCHIVELOG habilitado



\## Objetivo



Simular um incidente de perda de dados e praticar procedimentos de backup, validação e recuperação no Oracle, preservando os dados dos demais incidentes do laboratório.



\## Cenário



Foi criada a tabela `INC005\_RECOVERY\_TEST`, contendo três registros fictícios: financeiro, faturamento e auditoria.



O objetivo foi realizar um backup antes da perda dos dados, verificar sua integridade e executar procedimentos de recuperação.



\## 1. Backup com RMAN



Foi realizado um backup completo do banco, incluindo os archived redo logs, utilizando o comando:



&#x20;   BACKUP DATABASE PLUS ARCHIVELOG

&#x20;   FORMAT '/opt/oracle/oradata/rman\_backups/inc005\_%U.bkp';



Também foram gerados autobackups do Control File e do SPFILE.



\## 2. Validação dos backups



Os backups foram verificados por meio dos comandos:



&#x20;   LIST BACKUP SUMMARY;



&#x20;   RESTORE DATABASE VALIDATE;



&#x20;   RESTORE ARCHIVELOG ALL VALIDATE;



As validações terminaram sem erros, confirmando que o RMAN conseguiu ler os backups necessários para restaurar os datafiles e os archived redo logs verificados.



Os backup pieces foram copiados para o diretório persistente `/opt/oracle/oradata/rman\_backups/`.



\## 3. Tentativa de recuperação de tabela com RMAN



Foi registrado o SCN `6281347` como ponto de recuperação.



Em seguida, foi realizada uma tentativa de recuperação da tabela utilizando `RECOVER TABLE`, com uma instância auxiliar temporária.



A operação retornou o erro:



&#x20;   ORA-00441: Oracle Free Edition SID violation.



O RMAN tentou iniciar uma instância auxiliar com um SID diferente de `FREE`, o que não foi permitido pela edição utilizada.



A operação foi interrompida sem recuperar a tabela. Os dados originais permaneceram intactos.



\## 4. Restauração física de datafile



Como alternativa para praticar RMAN, foi realizada a restauração de uma cópia do datafile 15, pertencente ao tablespace `USERS`.



O arquivo original não foi sobrescrito.



Comandos utilizados:



&#x20;   RUN {

&#x20;       SET NEWNAME FOR DATAFILE 15 TO

&#x20;       '/opt/oracle/oradata/rman\_aux/users01\_restored.dbf';



&#x20;       RESTORE DATAFILE 15;

&#x20;   }



O RMAN concluiu a restauração com sucesso.



Foi confirmada a existência do arquivo restaurado, com aproximadamente 138 MB, no diretório auxiliar.



A tabela original continuou acessível, demonstrando que a restauração isolada não interrompeu o banco em funcionamento.



Essa operação restaurou uma cópia física do datafile, mas não realizou sua recuperação com redo nem substituiu o arquivo original.



\## 5. Simulação de exclusão acidental



Foi executada a exclusão controlada da tabela de teste:



&#x20;   DROP TABLE inc005\_recovery\_test;



Após a exclusão, uma tentativa de consulta retornou `ORA-00942`, confirmando que a tabela não estava mais acessível pelo nome original.



Foi verificado que a tabela havia sido preservada na Recycle Bin do Oracle.



\## 6. Recuperação utilizando Flashback



A tabela foi recuperada com o comando:



&#x20;   FLASHBACK TABLE inc005\_recovery\_test TO BEFORE DROP;



A operação foi concluída com sucesso.



Após a recuperação, foi executada uma consulta para confirmar a presença dos três registros originais.



Essa recuperação utilizou a Recycle Bin e não exigiu restauração de backup com RMAN.



\## Resultado



\- Backup completo realizado com RMAN.

\- Backups dos datafiles e archived redo logs validados.

\- Limitação da recuperação de tabela com RMAN no Oracle Free identificada e documentada.

\- Cópia física do datafile restaurada em diretório separado.

\- Tabela de teste excluída intencionalmente.

\- Tabela recuperada com Flashback.

\- Três registros originais confirmados após a recuperação.

\- Dados dos incidentes anteriores preservados.



\## Aprendizados



O laboratório permitiu praticar a preparação e validação de backups, compreender a diferença entre restauração física e recuperação lógica e investigar uma limitação da edição Oracle utilizada.



Também reforçou a importância de testar os procedimentos de recuperação e não considerar um backup válido apenas porque sua execução terminou sem erros.



\## Status



Resolvido — laboratório concluído com restauração de datafile via RMAN e recuperação de tabela via Flashback.

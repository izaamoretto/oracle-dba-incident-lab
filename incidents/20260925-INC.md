\# 20260925-INC — Falha de acesso por ausência de privilégio



\## Ambiente



\- Oracle Database 26ai Free em Docker

\- PDB: FREEPDB1

\- Usuário da aplicação: APP\_RELATORIOS

\- Proprietário da tabela: SYSTEM

\- Ferramenta: SQL\*Plus



\## Cenário



Foi simulada uma falha de acesso de uma aplicação a uma tabela existente. O usuário APP\_RELATORIOS possuía permissão para se conectar ao banco, mas não tinha privilégio de leitura sobre a tabela SYSTEM.INC008\_RELATORIO.



\## Reprodução



Após criar o usuário, conceder CREATE SESSION e preparar a tabela com um registro fictício, a aplicação tentou executar:



```sql

SELECT \* FROM system.inc008\_relatorio;

```



O Oracle retornou ORA-00942: table or view does not exist.



\## Diagnóstico



A existência da tabela foi conhecida durante a preparação do laboratório. Na sessão administrativa, foi consultada a DBA\_TAB\_PRIVS para verificar se APP\_RELATORIOS possuía privilégios sobre SYSTEM.INC008\_RELATORIO.



A consulta não retornou privilégios diretos para o usuário, confirmando a ausência do GRANT necessário no cenário simulado.



\## Correção



Foi concedido somente o privilégio de leitura:



```sql

GRANT SELECT ON system.inc008\_relatorio TO app\_relatorios;

```



Não foram concedidos privilégios de alteração ou exclusão, respeitando o princípio do menor privilégio.



\## Validação



Após o GRANT, a consulta foi executada novamente com APP\_RELATORIOS e retornou o registro esperado.



\## Resultado



Falha de acesso reproduzida, causa identificada e acesso de leitura restabelecido. Não foi necessário reiniciar o banco ou conceder permissões administrativas.

\## Aprendizados



O erro ORA-00942 pode ocorrer mesmo quando a tabela existe, caso o usuário não possua acesso ao objeto. A investigação dos privilégios permite corrigir o problema sem conceder permissões excessivas.

Incidente simulado resolvido e validado.
